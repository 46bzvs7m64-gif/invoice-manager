# 发票管家 · 软件开发计划

> 版本：v1.0（MVP）  |  日期：2026-09-21  |  目标周期：4 周

---

## 一、项目概述

### 1.1 项目目标
开发一款**个人发票智能管理工具**，自动从邮箱采集电子发票，通过大模型识别结构化信息，按开票对象自动归类，支持按对象/日期/金额检索，并可标记使用状态，避免重复报销。

### 1.2 目标用户
- 单人使用（无需多账号体系）
- 有报销/记账需求的个人用户
- 发票主要来源：QQ 邮箱 / 163 邮箱中的 PDF/OFD 附件

### 1.3 MVP 范围（第一期）
| 模块 | 纳入 MVP | 说明 |
|---|---|---|
| 邮箱配置 & 一键采集 | ✅ | QQ/163 邮箱 IMAP 授权码接入 |
| 发票附件下载 | ✅ | PDF/OFD 附件，黑名单过滤非发票 |
| 大模型识别 | ✅ | 通义千问 Qwen-VL 提取结构化字段 |
| 按开票对象归类 | ✅ | 销售方、购买方双维度 |
| 多条件检索 | ✅ | 对象、日期范围、金额区间、类型 |
| 标记已使用 | ✅ | 未使用 / 已使用 状态切换 |
| 发票预览与下载 | ✅ | 在线预览 PDF、下载到本地 |
| 定时自动采集 | ⏸️ 第二期 | MVP 先做手动一键采集 |
| iOS App 打包 | ⏸️ 第二期 | MVP 先做响应式 Web |
| 微信小程序 | ⏸️ 第三期 | |
| 正文链接下载 | ⏸️ 第二期 | MVP 仅处理附件型发票 |

## 二、技术选型

| 层级 | 技术 | 说明 |
|---|---|---|
| 后端 | Python 3.10+ · FastAPI · SQLAlchemy | 异步 Web 框架，RESTful API |
| 数据库 | SQLite | 零配置，单文件存储，适合个人使用 |
| 邮件采集 | imaplib + email（Python 标准库） | QQ/163 IMAP，授权码认证 |
| 发票识别 | 通义千问 Qwen-VL-Max API | 用户提供 API Key，按调用量计费 |
| 前端 | Vue 3 + Vite + Element Plus + Pinia | 响应式，PC/手机浏览器通用 |
| 部署 | 本地电脑运行 | 同局域网手机/PC 访问，零成本 |

## 三、阶段划分与交付计划

### 阶段 1：环境搭建 & 邮箱采集（第 1 周）

**目标**：跑通邮箱连接 → 过滤发票邮件 → 下载附件 全链路

**交付物**：
1. 后端项目骨架（FastAPI + SQLAlchemy + SQLite）
2. 邮箱配置模块（IMAP 地址、端口、授权码、SSL）
3. 邮件采集服务：
   - 按发件人域名 + 主题关键词过滤（"发票"、"invoice"、"电子发票"、"数电票"）
   - 增量同步（记录已处理邮件 UID，避免重复）
   - 下载 PDF/OFD 附件，按 PDF 魔数校验，过滤结账单/行程单
4. 前端：邮箱配置页 + 手动采集按钮

**验收标准**：
- [ ] 能成功连接 QQ/163 邮箱并拉取最近 30 天邮件
- [ ] 能正确识别并下载发票附件，过滤掉非发票邮件
- [ ] 下载的文件保存在本地指定目录，文件名含发票号
- [ ] 重复采集不会下载已处理过的邮件

---

### 阶段 2：大模型识别 & 数据入库（第 2 周）

**目标**：将下载的发票 PDF 通过大模型识别，提取结构化字段并入库

**交付物**：
1. OCR 识别服务：
   - 调用通义千问 Qwen-VL API，传入 PDF
   - 提取字段：发票号码、开票日期、金额（含税/不含税/税额）、销售方名称、销售方税号、购买方名称、购买方税号、发票类型、消费类目
   - 返回 JSON 结构化数据
2. 数据入库：
   - 发票元数据存入 SQLite
   - 发票文件路径存入记录
   - 去重逻辑（发票号码唯一，重复则跳过）
3. 前端：识别进度展示 + 发票列表初版

**验收标准**：
- [ ] 单张发票识别耗时 < 10 秒
- [ ] 关键字段识别准确率 ≥ 95%（发票号、日期、金额）
- [ ] 重复发票不会重复入库
- [ ] 识别失败的发票有错误日志，可重试

---

### 阶段 3：归类检索 & 标记使用（第 3 周）

**目标**：实现按开票对象归类、多条件查询、标记已使用

**交付物**：
1. 归类功能：
   - 按销售方自动分组
   - 按购买方自动分组
   - 支持手动编辑归类
2. 检索功能：
   - 按销售方/购买方筛选
   - 按日期范围筛选
   - 按金额区间筛选
   - 按发票类型筛选
   - 按使用状态筛选（未使用/已使用）
3. 标记使用：
   - 单张标记已使用/未使用
   - 批量标记
4. 前端：仪表盘 + 发票列表 + 筛选器 + 详情页

**验收标准**：
- [ ] 能按销售方/购买方查看分组统计
- [ ] 组合筛选能正确返回结果
- [ ] 标记已使用后，默认查询不再显示（可筛选查看历史）
- [ ] 移动端布局适配正常

---

### 阶段 4：预览导出 & 联调测试（第 4 周）

**目标**：完成发票预览、下载、整体流程联调与测试

**交付物**：
1. 发票预览：
   - 在线 PDF 预览
   - 下载到本地
2. 仪表盘统计：
   - 发票总数、总金额、未使用数量
   - 按月统计图表
3. 整体流程联调：
   - 配置邮箱 → 采集 → 识别 → 归类 → 查询 → 标记 全流程
4. 测试与文档：
   - 核心功能测试用例
   - 部署说明文档（启动后端、访问地址、API Key 配置）

**验收标准**：
- [ ] 完整流程跑通，无阻塞性 Bug
- [ ] PC 和手机浏览器（同局域网）均可正常使用
- [ ] 提供清晰的启动与使用说明
- [ ] 发票识别、归类、查询核心功能稳定可用

## 四、风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 大模型 API 识别准确率不足 | 字段错误影响查询 | 提供手动编辑字段功能；关键金额字段支持人工校验 |
| 邮箱 IMAP 限制连接频率 | 采集失败 | 采集间隔 ≥ 1 分钟；支持断点续采 |
| 本地电脑关机导致服务不可用 | 手机无法访问 | MVP 阶段明确此限制；后续提供云服务器迁移方案 |
| OFD 格式发票无法直接喂给大模型 | 识别失败 | OFD 转 PDF 后再识别；或标记为"需人工处理" |
| 发票 PDF 有密码保护 | 无法解析 | 检测到加密 PDF 时提示用户输入密码或跳过 |

## 五、后续迭代方向（非 MVP）

1. **定时自动采集**：后台定时任务，每日自动检查新发票
2. **iOS App 打包**：Capacitor 打包，支持本地文件系统保存
3. **微信小程序**：uni-app 复用前端代码
4. **正文链接下载**：解析邮件正文中的下载链接（如中石化数电票）
5. **报销单导出**：按条件批量导出 Excel 报销清单
6. **云服务器部署**：迁移到阿里云/腾讯云，支持外网随时访问
